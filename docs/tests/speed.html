⚡ Snelheid

Hoe snel kan elk model lezen (prompt processing) en schrijven (generatie)? Gemeten met llama-bench op dezelfde hardware.

Wat test dit?

De snelheidstest meet prompt processing tokens per seconde (pp512 = hoe snel het model een 512-token prompt verwerkt) en generatie tokens per seconde (tg128 = hoe snel het model 128 nieuwe tokens genereert). Dit is een pure hardware+software-throughput test via llama-bench — er komt geen intelligentie of correctheid aan te pas.

De test draait lokaal op de C4130 (4× NVIDIA Tesla V100-SXM2-32GB, 128GB dedicated VRAM). Alle modellen draaien volledig op GPU (-ngl 999) met de hoogste kwantisatie die past.

🏆 Winnaar

Nemotron-3.5-Lightning-30B-A3B — Snelste in alles

142 t/s generatie én 1815 t/s prompt processing — de snelste van alle 7 modellen, op maar 25.5GB. Het 3B-actieve MoE-ontwerp leest per token maar een fractie van de gewichten.

GPT-OSS-120B (110 t/s) is de snelste van de grote modellen, maar de 70B/72B dense modellen (16 t/s) vallen ~9× terug.

Wat onthult deze test?

MoE vs Dense op bandbreedte-gelimiteerde hardware

Het meest fundamentele patroon in de hele benchmark-suite: MoE-modellen zijn ~7-9× sneller dan dense modellen op deze hardwareklasse. De C4130 heeft ~900 GB/s bandbreedte per GPU (HBM2) — ruim, maar niet oneindig. Een dense model moet álle parameters per token lezen; een MoE-model activeert slechts een fractie.

  • Llama-3.3-70B (dense, 70B actief): 16 t/s — leest ~70GB per token
  • Nemotron-3.5 (MoE, ~3B actief): 142 t/s — leest ~3GB per token
  • Dat is ~9× sneller met een kleinere footprint (42.5 vs 25.5GB)

Dit is géén kritiek op dense architecturen — het is een harde fysieke realiteit bij ~900 GB/s per GPU. Op een H100 (3.3 TB/s) zou het verschil veel kleiner zijn.

BF16 heeft op Volta géén zin

De V100 (sm_70) heeft geen BF16-hardware — BF16 wordt geëmuleerd. Dat zie je direct in de cijfers: Qwen3.8-27B-BF16 (53.8GB) draait 15 t/s, terwijl dezelfde model in Q8_0 (28.6GB) 24 t/s haalt. De halve schijfruimte is 1.6× sneller. Op Volta: quantiseer, en vermijd BF16-KV.

Methodologie

llama-bench -m <model>.gguf -ngl 999

Dit draait de standaard pp512 + tg128 benchmark van llama.cpp: verwerk 512 tokens (prompt), genereer er 128 (generatie). De output is het gemiddelde van meerdere runs. Alle lagen op GPU (-ngl 999), geen CPU-offload.

Alle 7 modellen draaien volledig in de 128GB dedicated VRAM; Nemotron-3-Super-120B-A12B (82.5GB) is de grootste. Modellen boven ~80GB zijn bewust buiten beschouwing gelaten, met de Nemotron-3-Super als enige expliciete uitzondering.
