Wat test dit?

Vier taken die elk een combinatie van vaardigheden vereisen — je kunt niet "één ding goed doen" en slagen. Dit is de meest discriminerende testcategorie: modellen die hier falen, vallen op meerdere dimensies door de mand.

De 4 taken

  1. Multi-stap rekenen: Drie ploegen met wisselende snelheden, pauzes, en starttijden — hoeveel pakketten totaal?
  2. LRU-cache implementatie: Schrijf een Python klasse met O(1) get/put operaties
  3. Notulen-structurering: Transformeer een raadsvergaderingstranscript naar gestructureerde notulen
  4. Strikte JSON-instructies: Produceer exact gespecificeerde JSON met woordlimiet, veldvalidatie

Wat onthult deze test?

Thinking: zegen en vloek

De harde taken onthullen de dualiteit van thinking-modus. Met de default thinking-modus AAN keerden de reasoning-modellen (Nemotron, Qwen) lege content op de formaat-taken (notulen-structurering en strikte JSON) — het denkproces at het volledige 3000-tokenbudget op vóór er een antwoord kwam. De zware rekenvraag (antwoord 2195) lukt daarentegen alléén mét thinking aan.

De fix: thinking uit voor formaat-taken

Door chat_template_kwargs: {enable_thinking: false} alléén voor de formaat-taken in te stellen, ging Nemotron-3.5-Lightning van 1/4 naar 4/4. Dit bevestigt dat thinking-modus bij gestructureerde output (notulen, JSON) contraproductief is: het denkproces concurreert met het antwoord om hetzelfde tokenbudget.
